# 세이브 마이그레이션

- 스키마: 기존 `v:3` → `v:4`. `Sim.migrate(save)`가 한 단계씩 올린다. v3보다 오래된 판은 `null`을 돌려 주고 화면이 안내한다.
- v3 → v4에서 하는 일: 병력 객체에 `adv: 0` 추가, 원장 초기화(현재 보유량을 기준점으로), `scenarioId` 기록, `s.dom` 유도 초기화, `migratedFrom: 3` 표시.
- `s.dom`은 기존 값에서만 유도한다. `controller`·`overlord`·`lord`·`autonomy`·국고는 건드리지 않는다. 명목 종주와 실효 지배가 다른데 약정이 없으면 `UNRESOLVED_RIGHTS`를 `s.dom.audit`에 남기고 직할로 만들지 않는다.
- 멱등성: 같은 세이브를 두 번 올려도 결과가 같고, 저장→불러오기→저장이 바이트 단위로 같다. 월간 정비 중에 저장한 판을 불러와도 결산 ID·예약 명령이 유지되고 이어서 진행한 결과가 원본과 같다(QA `SAVE-MIGRATION`, `G1-TIME-03`, `G1-DETER-01`).
- 되돌리기: v4 세이브는 R3 빌드에서 열리지 않는다(R3은 `v===3`만 받는다). 새 빌드는 저장 키를 `sgk-g1-*`로 따로 써서 R3의 저장(`sgk-p0r-*`)을 덮어쓰지 않는다. 아티팩트는 서로 다른 주소라 브라우저 저장소도 분리돼 있다.
